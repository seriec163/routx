# Установка и удаление агента RoutX

Поддерживаются обе схемы пакетов OpenWrt:

* OpenWrt 24.10 и older — `opkg` (`routx-agent.ipk`);
* OpenWrt 25+ / apk-based — `apk` (`routx-agent.apk`).

Во всех случаях `/etc/config/routx` с привязкой сохраняется.

Пакеты агента раздаёт **сама панель**: `/agent/install.sh`,
`/agent/routx-agent.ipk`, `/agent/routx-agent.apk` и
`/agent/routx-agent.tar.gz`. Они собираются при сборке образа панели
(`/app/agent/dist`). GitHub используется только как источник образа панели;
роутер напрямую с GitHub агент не скачивает. Самообновление агента также идёт
через публичный адрес панели.

Администратор может обновлять агента на своих роутерах и на роутерах
пользователей своей ветки: «Развёртывание» → «Агент RoutX на клиентских
роутерах». Суперадминистратор видит там все роутеры.

## Установка через установщик RoutX

Стандартная команда из панели сама определяет менеджер пакетов:

```sh
wget -qO- https://routx.example/agent/install.sh | sh -s -- \
  --server https://routx.example --token <token> --reboot
```

`--reboot` перезагружает роутер после успешной привязки. Без него
установщик просто напишет, что нужно выполнить `reboot`.

### Если на роутере уже установлены продукты

Установщик находит **все** установленные продукты и показывает:

```text
На роутере найдено несколько продуктов:
  1) Prokop 2.32.0
     пакеты: prokop luci-app-prokop luci-i18n-prokop-ru
  2) Tachyon 1.7.11
     пакеты: tachyon luci-app-tachyon luci-i18n-tachyon-ru tachyon-core
Какой продукт оставить активным? [1]:
```

После выбора установщик:

1. останавливает и отключает лишние продукты;
2. удаляет их пакеты, ядра и LuCI-файлы;
3. удаляет конфиги, состояние, кэш, cron-задания и nft-таблицы этих
   продуктов;
4. оставляет выбранный продукт активным и запускает его;
5. продолжает установку агента RoutX.

Для автоматической установки без вопроса используйте `--keep`:

```sh
wget -qO- https://routx.example/agent/install.sh | sh -s -- \
  --server https://routx.example --token <token> \
  --keep tachyon --reboot
```

`--product` нужен, когда продуктов ещё нет и надо выбрать, что установить.
Если на роутере уже есть один продукт, `--product` с другим именем не
переключает его: установщик сообщит, что один роутер — один продукт.

Конфиг без бинарника, службы или пакета больше не считается установленным
продуктом — иначе старые `*.routx-removed-*` и остатки конфигов давали
ложный конфликт.

Установщик:

1. Проверяет `opkg` или `apk`.
2. Проверяет реальную загрузку модулей ucode: `digest`, `fs`, `uci`.
   Недостающие пакеты доустанавливает через `opkg update`/`apk update`.
   Если `ucode-mod-digest` поставить не удалось, установка останавливается
   с понятной ошибкой: без него агент не подпишет запросы и не привяжется.
3. `timeout` больше не обязателен: если `coreutils-timeout` нет,
   `/usr/libexec/routx-agent-exec` использует shell-сторожевой таймер.
4. Скачивает `.ipk`, `.apk` и `.tar.gz`.
5. На `opkg` ставит `routx-agent.ipk`.
6. На `apk` ставит `routx-agent.apk`:

```sh
apk add --upgrade --allow-untrusted --force-overwrite ./routx-agent.apk
```

6. Если пакетный менеджер недоступен или установка не удалась, использует
   `routx-agent.tar.gz`, сохраняя старый `/etc/config/routx`.
7. После успешной привязки перезагружает роутер, если передан `--reboot`.
   Панель добавляет этот флаг в команду установки автоматически: LuCI и
   продукт должны применить изменения после перезагрузки.

## Обновление вручную

OpenWrt 24.10 / opkg:

```sh
wget -qO /tmp/routx-agent.ipk https://routx.example/agent/routx-agent.ipk
opkg install --force-reinstall /tmp/routx-agent.ipk
/etc/init.d/routx-agent restart
```

OpenWrt 25+ / apk:

```sh
wget -qO /tmp/routx-agent.apk https://routx.example/agent/routx-agent.apk
apk add --upgrade --allow-untrusted --force-overwrite /tmp/routx-agent.apk
/etc/init.d/routx-agent restart
```

Конфиг `/etc/config/routx` в apk-пакете намеренно не поставляется: его
создаёт `90-routx-agent`, а при обновлении существующий файл не перезаписывается.

## Обновление из панели

Панель раздаёт собранный в её образе пакет агента:

```text
/agent/routx-agent.ipk
/agent/routx-agent.apk
/agent/routx-agent.sha256
/agent/routx-agent.version
```

На странице **«Развёртывание и перенос»** есть блок «Агент RoutX на клиентских
роутерах»: отметить роутеры и нажать «Обновить выбранные».

Как это работает:

1. Панель создаёт задачу `agent_update`.
2. Агент скачивает `.sha256` и свой пакет по HTTPS.
3. Проверяет SHA-256.
4. Запускает установку отдельным процессом: `opkg install --force-reinstall`
   или `apk add --allow-untrusted` (с fallback на `--force-overwrite`).
5. Перезапускает `routx-agent`; результат пишется в
   `/var/log/routx-agent-update.log`.
6. Панель ждёт, пока в списке роутеров появится новая версия.

Важно: первый переход на self-update выполняется вручную. Агенты **ниже
1.5.0** не обновляются из панели автоматически: их нужно один раз обновить
вручную (команды выше или установщик). Начиная с **1.5.0** обновление из
панели работает.

## Удаление

opkg:

```sh
opkg remove routx-agent
```

apk:

```sh
apk del routx-agent
```

Скрипт `pre-deinstall`/`prerm` останавливает и отключает `routx-agent` перед
удалением. Если использовался tar-фолбэк без пакетного менеджера, удаляйте
файлы вручную:

```sh
/etc/init.d/routx-agent stop
/etc/init.d/routx-agent disable
rm -rf /usr/lib/routx-agent /usr/bin/routx-agent /etc/init.d/routx-agent \
  /etc/uci-defaults/90-routx-agent /www/luci-static/resources/view/routx-agent
# /etc/config/routx удаляйте только если действительно хотите сбросить привязку
```

## Проверка

```sh
routx-agent version
routx-agent status
```

Ожидаемая версия:

- **1.1.0+** — DNS-бенчмарк;
- **1.1.1+** — автозапуск продукта; sing-box запускается самим Prokop/Forkop,
  его standalone-автозапуск продукт отключает штатно;
- **1.1.2+** — безопасное слияние подключений: сохраняются чужие VLESS-ссылки и
  не создаются дубликаты подписок, уже добавленных в секцию вручную;
- **1.1.3+** — исправлен автозапуск: агент больше не пытается включить
  standalone-автозапуск sing-box (в 1.1.2 он включался, но Prokop/Forkop всё
  равно снимал его при следующем старте);
- **1.1.4+** — здоровье и быстрая диагностика учитывают, что sing-box
  управляется продуктом: выключенный `S99sing-box` при запущенном
  Prokop/Forkop больше не считается деградацией;
- **1.1.5+** — домены секции пишутся в новый combined-формат `domain`
  (`full:`, `keyword:`, `regex:`), старые `domain_keyword`/`domain_regex`
  удаляются при следующем применении;
- **1.1.6+** — DNS-бенчмарк использует DoH по IP-адресам
  (`https://1.1.1.1/dns-query` и т.п.), до трёх основных DNS и фиксированный
  bootstrap: `77.88.8.8`, `8.8.4.4`, `1.1.1.1`, `9.9.9.9`;
- **1.1.7+** — полное управление подключениями: список подписок и прямых
  ссылок, замена и удаление с маскированием секретов;
- **1.1.8+** — в мониторинге прокси группа показывается по label секции
  (`router_control`), а не по внутреннему тегу `gga-out`;
- **1.2.2+** — публичные IP напрямую и через VPN, задержка активного сервера,
  принудительный замер по кнопке «Тест пинга»;
- **1.2.3+** — проверка доступности нескольких сайтов через активный VPN;
- **1.2.4+** — self-update из панели: скачивание пакета, SHA-256, установка
  через opkg/apk и перезапуск агента;
- **1.2.5+** — исправлен self-update (сборка update-скрипта), проверено
  обновление клиентского роутера из панели;
- **1.2.6+** — очищены сообщения клиента после миграции; обновление
  1.2.5 → 1.2.6 проверено через панель;
- **1.2.7+** — установка на минимальные прошивки: пакет больше не требует
  `coreutils-timeout`, `timeout` имеет shell-фолбэк, установщик проверяет и
  доустанавливает модули ucode, а ошибка привязки видна в `status.json`;
- **1.2.8+** — фолбэк `timeout` больше не держит pipe LuCI: QR и другие
  действия в LuCI завершаются сразу, а не через 30 секунд; запросы
  мобильного QR/устройств ограничены 15 секундами;
- **1.2.9+** — поддержка Podkop: определение продукта, мониторинг,
  диагностика, чтение секций и подключений, установка официальным
  скриптом с проверками OpenWrt 24.10+, свободного места и
  `https-dns-proxy`;
- **1.3.0+** — редактирование Podkop через RoutX: секции, домены/IP,
  community-списки и подключения. После записи выполняется
  `podkop reload`, проверка `sing-box check` и состояния службы;
  при ошибке конфиг восстанавливается из локального снимка;
- **1.3.1+** — агент резолвит домен панели напрямую через публичный DNS
  и передаёт `curl --resolve`. Это обходит FakeIP Podkop, из-за которого
  системный DNS мог вернуть `198.18.x.x` и разорвать связь с RoutX;
- **1.3.2+** — поддержан режим Podkop `outbound` (готовый JSON outbound,
  перенесённый из LuCI/Prokop). RoutX сохраняет его и не перезаписывает
  ссылками; редактирование доменов и списков работает как обычно;
- **1.3.3+** — замена `outbound_json` из RoutX: агент проверяет JSON,
  делает снимок, переключает секцию в режим outbound, выполняет
  `podkop reload` и `sing-box check`, при ошибке откатывает конфиг;
- **1.3.4+** — Podkop reload ждёт фоновое обновление community-списков:
  если sing-box не стартовал из-за ещё не скачанных rule-set, агент
  повторяет проверку и reload до 90 секунд. Неподдерживаемые Podkop
  списки (github, supercell) отфильтровываются;
- **1.3.5+** — при ошибке Podkop reload в сообщение добавляется хвост
  лога `logread -e podkop`, чтобы видеть причину (несовместимый список,
  ошибка ссылки, сбой запуска sing-box). Ожидание старта увеличено
  до 120 секунд;
- **1.3.6+** — импортированные ссылки проверяются перед записью;
  варианты `httpupgrade`/`xhttp` пропускаются, если установленный
  sing-box их не поддерживает;
- **1.3.7+** — при ошибке Podkop reload агент ищет временный конфиг
  sing-box и добавляет в сообщение причину invalid-конфига;
- **1.4.0+** — подключения в правилах содержат статус из Clash API:
  активное подключение, задержку из истории sing-box и доступность.
  Добавлено переключение активного прокси через `set_group_proxy`;
- **1.4.1+** — режим `outbound_json` показывается как отдельная
  read-only строка подключения «JSON outbound» со статусом и задержкой;
- **1.4.2+** — для Podkop читаются только ссылки активного режима
  (`url`/`selector`/`urltest`/`outbound`); устаревшие списки других
  режимов больше не попадают в интерфейс;
- **1.4.3+** — если у секции один обычный outbound (режимы url/outbound),
  мониторинг замеряет его задержку через Clash API, чтобы PWA показывал
  пинг и для `JSON outbound`;
- **1.4.4+** — добавление/замена подписки в секции `outbound_json`
  автоматически переключает её на `selector` и удаляет старый JSON
  outbound;
- **1.4.5+** — поддержка Forkop 2.x: новый формат Clash API
  (`forkop clash_api METHOD PATH`), корректные статусы службы, пинг,
  выбор активного сервера и отображение подключений;
- **1.4.6+** — группы Forkop 2.x находятся по label секции, а не по
  старому имени `<section>-out`; выбор сервера принимает человекочитаемые
  теги с пробелами и кириллицей;
- **1.4.8+** — серверы из встроенной подписки Forkop 2.x показываются
  в подключениях RoutX без служебного префикса провайдера: название,
  пинг и активный сервер;
- **1.4.9+** — выбор сервера принимает человекочитаемые теги Forkop 2.x
  без ошибок разбора регулярного выражения;
- **1.4.10+** — проверка доступа к сайту через активный сервер Forkop 2.x
  использует новый Clash API;
- **1.4.11+** — серверы из подписки помечаются как нативные: их нельзя
  удалить или заменить по одному, но можно выбрать активным;
- **1.4.12+** — IP через VPN для Forkop 2.x берётся из Clash API
  (`/proxies/.../exit`), а не из второго запуска sing-box;
- **1.5.0+** — поддержка Tachyon: определение продукта, `tachyon-core`
  как ядро, Clash API, статус службы, списки и переключение
  Podkop/Forkop/Prokop → Tachyon через официальный установщик;
- **1.5.1+** — Tachyon читается из `/etc/config/tachyon`, а агент
  перезапускается после смены продукта, чтобы сразу определить Tachyon;
- **1.5.2+** — JSON-outbound Tachyon/Forkop 2.x отображается в списке
  подключений с тегом, пингом и активным состоянием;
- **1.5.3+** — после смены продукта на Tachyon JSON-outbound удаляется
  из секций: RoutX всегда использует подписку, а не JSON-конфигурацию;
- **1.5.4+** — подписка Tachyon применяется как источник, без дублирующих ссылок;
- **1.5.5+** — при смене продукта RoutX переносит общие настройки секции
  (списки, домены, пользовательские адреса) и затем применяет подписки;
- **1.5.6+** — подписка получает имя при переносе на Forkop, а после
  применения подключений RoutX запускает службу продукта;
- **1.5.8+** — при переходе на Podkop удаляются ядра Tachyon/Forkop и
  ставится sing-box (при нехватке места — sing-box-tiny);
- **1.5.9+** — подписка Tachyon записывается в `outbound_source`, без
  JSON и без дублирования ссылок;
- **1.5.17+** — при смене продукта поддерживается Prokop: старый пакет
  удаляется, официальный установщик Prokop ставится с `--lang ru`, а
  настройки и подписки восстанавливаются как у Forkop;
- **1.5.19+** — при переходе на Tachyon удаляются пакеты Prokop/Podkop/Forkop,
  установка ждёт завершения обновления списков и затем запускает Tachyon;
- **1.5.20+** — при переходе на Prokop sing-box ставится заранее с
  `--force-space`, поэтому установка не упирается в расчёт свободного места;
- **1.5.21+** — при установке Prokop снимается зависший nft-guard
  `ProkopConfigRestoreDpiGuard`, из-за которого health оставался `error`;
- **1.5.22+** — при уходе с Prokop удаляется и пакет `luci-i18n-prokop-ru`;
- **1.5.23+** — self-update доустанавливает модули ucode и перезапускает
  агент даже при ошибке пакетного менеджера; postinst сам поднимает службу;
- **1.5.24+** — агент сообщает список установленных продуктов и пакетов,
  умеет удалять выбранные пакеты и возвращает, что было удалено при смене
  продукта;
- **1.5.25+** — при старте Tachyon автоматически переносит legacy
  `subscription_url` от Forkop в native `outbound_source`, чтобы после смены
  продукта создавалась прокси-группа;
- **1.5.26+** — при смене продукта агент сохраняет все секции и источники
  независимо от их имён и переносит их в целевой продукт: секции, списки,
  домены, подписки и ссылки;
- **1.5.27+** — после миграции/старта Tachyon агент запускает
  `subscription_update_if_due`, чтобы подписка сразу превратилась в прокси.

## Частые ошибки установки

`pkg_hash_check_unresolved: cannot find dependency ucode-mod-digest`:

```sh
opkg update
opkg install ucode-mod-digest
ucode -e 'require("digest"); print("ok\n")'
```

`cannot find dependency coreutils-timeout` в версиях до 1.2.7:

```sh
opkg update
opkg install coreutils-timeout
```

Если после установки агент не привязался, смотрите:

```sh
/etc/init.d/routx-agent restart
routx-agent status
cat /var/run/routx-agent/status.json
logread -e routx-agent | tail -20
```

Токен привязки одноразовый и живёт 5 минут: после истечения выпустите новый
в панели и повторите команду установки.
