# Диагностика Prokop: частые «ложные» предупреждения

RoutX переводит вывод `prokop global_check` на русский и добавляет
пояснения к проверкам, которые легко понять неправильно.

## `Rules mangle counters`

Prokop предупреждает, если счётчики в цепочке `mangle` равны нулю. Эта цепочка
считает **перенаправленный трафик LAN-клиентов** (hook `prerouting`).

Сам `global_check` запускает `curl` с роутера. Такой трафик идёт через
`output`/`mangle_output`, а не через `mangle`. Поэтому счётчик `mangle` может
остаться нулевым при полностью исправных правилах.

Как проверить:

```sh
nft list chain inet ProkopTable mangle
nft list chain inet ProkopTable proxy
nft list chain inet ProkopTable mangle_output
```

Если в `proxy` или `mangle_output` счётчики растут, правила работают. Для
чистой проверки откройте сайт с устройства, которое использует этот роутер как
шлюз, и запустите диагностику снова.

Если все счётчики нулевые и LAN-клиенты действительно ходят через роутер,
проверьте:

* клиенты используют DNS роутера, а не сторонний DoH;
* в Prokop выбраны нужные интерфейсы (`source_network_interfaces`);
* правила community-списков действительно содержат нужные подсети.

## `Sing-box autostart disabled`

Prokop и Forkop сами запускают sing-box и при каждом старте отключают его
standalone-автозапуск:

```text
Disabling standalone sing-box autostart
```

Поэтому:

* ✅ `Sing-box autostart disabled` — норма: отдельный автозапуск выключен,
  sing-box поднимает продукт;
* ❌ `Sing-box autostart disabled` — отдельный автозапуск ещё включён; продукт
  снимет его при следующем старте.

В RoutX автозапуск устроен так же: включается Prokop/Forkop, а он
поднимает sing-box. Отдельная галочка sing-box не нужна.

## Где смотреть в RoutX

На странице роутера откройте **Диагностика → Быстрая диагностика**. Под
спорными пунктами будет пояснение на русском. Общий статус считается по строкам
`✅` / `⚠️` / `❌`, поэтому пояснения не скрывают реальные ошибки.
