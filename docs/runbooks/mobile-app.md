# Мобильное приложение (PWA)

## Что это

Мобильный интерфейс RoutX: `/#/app`. Он же открывается при установке
PWA на телефон. Панель для компьютера остаётся на прежних адресах (`/#/routers`
и другие) и не меняется.

Экраны:

* **Главная** — выбор роутера, статус, время, протоколы подключения,
  IP без VPN и через VPN, задержка активного сервера, доступность сайтов,
  тест пинга, перезапуск VPN, быстрый переход к обходу.
* **Обход** — домены, IP и подсети, которые открываются напрямую, минуя VPN.
* **Роутеры** — список роутеров и добавление нового по QR или ссылке.

Нижняя навигация: «Главная / Обход / Роутеры».

## Экран и прокрутка

Приложение ведёт себя как нативное, а не как страница браузера:

* `body` фиксируется на размер экрана, страница не прокручивается и не
  «оттягивается» за границы;
* `.m-app` растянут на 100% зафиксированного body, а не на `100dvh`:
  в standalone-режиме iOS `dvh` иногда оставлял полосу внизу экрана;
* прокручивается только содержимое `.m-screen`;
* нижняя навигация доковая — прижата к нижнему краю, а её
  `padding-bottom` учитывает `safe-area-inset-bottom` и домашний индикатор;
* учтены `safe-area-inset-top` и `safe-area-inset-bottom` (вырез, домашний
  индикатор);
* поля ввода имеют размер шрифта 16px — iOS Safari не зумит страницу при
  фокусе;
* `overscroll-behavior: none` отключает pull-to-refresh и горизонтальный
  сдвиг страницы.

## Выбор роутера

Выбранный роутер хранится в `localStorage` браузера (`rc.mobile.router`).
Если он не найден или архивирован, приложение выбирает первый роутер в сети.

## Обход

Экран работает с **уже созданными секциями** Prokop. Приложение:

1. Читает живые правила с роутера при входе на экран.
2. Показывает список секций с их действием: «через VPN», «напрямую»,
   «блокировка», «только DNS».
3. При добавлении или удалении адреса сначала перечитывает правила,
   затем дописывает запись в выбранную секцию. Новые секции приложение
   не создаёт: если секций нет, оно предлагает создать их в полной панели.
4. Применяет изменение через `diff → confirm → apply` с прогрессом.
5. Не перезагружает VPN: Prokop подхватывает новое правило сам.

Выбранная секция запоминается для каждого роутера в
`localStorage` (`rc.mobile.section.<router-id>`). Свежее чтение перед
изменением защищает от затирания чужих правок и от создания дубликата
секции.

Домены можно вставлять ссылкой — приложение возьмёт только hostname.
Поддерживаются `example.com`, `*.example.com`, IPv4, IPv6 и подсети `a.b.c.d/n`.

## Задержка и публичные IP

**Задержка** — это задержка **активного** сервера выбранной группы, а не
медиана всех серверов. Кнопка «Тест пинга» запускает принудительный замер
(`monitor_probe` с `force: true`) и не использует кэш агента.

**IP без VPN** — публичный адрес прямого выхода роутера
(`direct-out`/`bypass-out`). **IP через VPN** — публичный адрес активного
выхода (`gga-out`) через `sing-box tools fetch`.

Агент получает оба адреса через временную копию конфига sing-box:
каталог `0700`, файл `0600`, после проверки удаляется. Секреты наружу
не передаются. Результат кэшируется на 5 минут, при ручном тесте
обновляется принудительно.

## Доступность сайтов

На главном экране есть карточка «Сайты · через VPN». По умолчанию:
Instagram, YouTube, LinkedIn. Для каждого адреса показывается зелёный
или красный индикатор и задержка через активный VPN-сервер.

Проверка идёт через Clash API Prokop (`get_proxy_latency`) тем же
активным outbound, что и трафик. Недоступный сайт не ломает проверку
остальных.

Кнопка **«Настроить»** раскрывает карточку:

* адреса меняются местами перетаскиванием за ручку ⠿;
* × убирает сайт (минимум один);
* можно добавить любой `http(s)`-адрес, до 8 штук;
* список хранится в `localStorage` отдельно для каждого роутера
  (`rc.mobile.sites.<router-id>`).

Проверка запускается при открытии приложения и по кнопке «Проверить».
После изменения списка проверка запускается повторно.

## Подключения и замена подписки

На главном экране показываются все подключения роутера: подписки и
VLESS-ссылки из всех секций. В одной секции их может быть несколько.

Для каждой строки видно:

* тип (`Подписка` или `VLESS`);
* название и секцию;
* замаскированный адрес и хвост ссылки;
* признаки «нет на роутере» и «выключено».

Кнопка **«Заменить»** открывает лист с полем для новой ссылки:

* для управляемого подключения RoutX вызывает
  `PATCH /api/v1/routers/{id}/connections/{connectionId}`;
* для внешней подписки/ссылки — `POST …/connections/manage` с
  `action: replace`;
* старый сервер после успешного apply больше не используется;
* секрет старой ссылки в приложении не показывается.

Так можно заменить один из нескольких серверов, не трогая остальные
подключения и не пересоздавая секцию.

## Стартовый экран и установка PWA

`start_url` манифеста — `/#/app`. После обмена QR-токена приложение сразу
открывает главный экран, а не отдельную страницу установки.

Если PWA ещё не установлено, сверху показывается плашка **«Установить RoutX»**
с кнопкой **«Инструкция»**. Инструкция открывается мобильным листом в стиле
приложения: Android, iPhone/Safari, компьютер и запуск с домашнего экрана.
В установленном PWA (`display-mode: standalone`) плашка скрыта.

## Уведомления и история

В шапке всех экранов есть колокольчик. Счётчик показывает непрочитанные,
а нажатие открывает лист **«Уведомления»**:

* история событий с роутером, временем и важностью;
* нажатие отмечает запись прочитанной;
* «Прочитать все» и × для удаления;
* кнопка **«Включить»** подписывает устройство на Web Push;
* кнопка **«Проверить»** отправляет тестовое push-уведомление.

История работает и без push: события сохраняются на сервере и видны в
приложении. Push нужен, чтобы получать их при закрытом приложении.
На iPhone он доступен только в установленном PWA (iOS 16.4+).

Подробнее: `docs/runbooks/notifications.md`.

## Обновление установленного PWA

Удалять приложение с домашнего экрана не нужно. На главном экране есть
карточка **«Приложение RoutX» → «Обновить»**:

* проверяется новый `sw.js`;
* новый service worker активируется, приложение перезагружается;
* cookies, `localStorage`, вход и привязка устройства сохраняются;
* повторное сканирование QR не требуется.

Если обновление не сработало, закройте PWA полностью (свайп из списка
открытых приложений) и откройте снова — iOS применяет новый service
worker при следующем запуске.

## Добавление роутера

* **Сканер QR** — камера телефона. Кнопка QR на главном экране сразу
  открывает сканер, а `getUserMedia` вызывается из жеста нажатия, поэтому
  камера запускается без второй кнопки. Браузер спрашивает разрешение
  один раз; дальше используется уже выданное разрешение. Если разрешение
  отозвано, показывается кнопка «Попробовать снова». Работает по HTTPS;
  если `BarcodeDetector` нет (Safari на iOS), используется `jsQR`.
* **Ссылка** — вставьте ссылку с QR (`…/#/install?token=…&router=…`) или сам
  токен. Токен одноразовый, живёт 5 минут и выпускается на роутере:
  LuCI → Служба → RoutX → «Показать QR для телефона».

После обмена токена создаётся обычная сессия, роутер становится выбранным.

## Ограничения

* Отдельной роли «член семьи» нет: приложение работает под учётной записью
  владельца.
* Сканер QR требует HTTPS. На HTTP доступен только ручной ввод ссылки.
* Приложение не создаёт и не удаляет секции — только редактирует списки
  существующих. Секции создаются в полной панели RoutX.
* Поддерживаются действия `connection`, `bypass`, `block`, `dns`. Секции
  с другими действиями (например, `zapret`) в мобильном редакторе не
  показываются.
* «Перезагрузить роутер» отправляет агенту команду `reboot` с задержкой 3 с,
  чтобы результат задачи успел уйти на сервер. Связь восстанавливается сама
  примерно через минуту.
