# Развёртывание и перенос на другой сервер

Раздел доступен только суперадминистратору: **Администрирование → Развёртывание**.

## Где это работает

Панель запускается в Docker Compose одинаково на OpenWrt (Docker на роутере
или мини-ПК с OpenWrt) и на VPS. Перенос не зависит от ОС: важны только
Docker, домен и доступ к панели. Файл переноса создаётся и применяется из
интерфейса, без shell-скриптов.

Минимальные требования к новому серверу:

* Docker и Docker Compose;
* тот же домен, направленный на новый сервер (после импорта);
* место под образ и том `rc_data`;
* тот же `POSTGRES_PASSWORD` в `.env` (или свой — база восстанавливается
  внутри контейнера, пароль влияет только на подключение).

## Что переносится

Один файл `.rcbackup` содержит:

* полный дамп PostgreSQL (пользователи, роутеры, подключения, шаблоны, задачи, аудит,
  настройки, отчёты диагностики);
* мастер-ключ шифрования (`RC_MASTER_KEY`) — без него нельзя расшифровать ссылки
  подключений и TOTP-секреты;
* служебные сведения: версия панели, версия схемы, публичный адрес, отпечаток ключа,
  количество записей.

Файл зашифрован парольной фразой (AES-256-GCM, ключ через scrypt). Парольная фраза
нигде не сохраняется: без неё файл бесполезен.

## Экспорт

1. Откройте **Развёртывание**.
2. Придумайте парольную фразу не короче 12 символов и повторите её.
3. Нажмите «Скачать файл переноса».
4. Сохраните файл и парольную фразу в разных местах.

## Импорт на новом сервере

1. Поднимите RoutX на новом сервере с тем же доменом:
   `RC_PUBLIC_URL=https://тот-же-домен`, `RC_COOKIE_SECURE=true`,
   тот же `POSTGRES_PASSWORD`, новый `RC_MASTER_KEY` (любой, ≥32 символов).
2. Войдите в панель нового сервера под суперадминистратором.
3. Откройте **Развёртывание → Импорт**, выберите файл, введите парольную фразу,
   нажмите «Проверить файл».
4. Проверьте источник, дату и количество записей. Введите слово `ПЕРЕНЕСТИ`
   и нажмите «Перенести данные».
5. Сервер заменит базу, запишет мастер-ключ из файла и перезапустится.
   Страница сама дождётся `/readyz` и перезагрузится.

Перед заменой автоматически создаётся страховочная копия текущей базы:
`/app/data/pre-import-*.rcbackup` (том `rc_data`). При ошибке импорта база
откатывается из дампа, снятого перед заменой.

## Бесшовность

* Домен остаётся тем же, поэтому cookie-сессии и входы пользователей
  сохраняются: после переключения DNS панель открывается уже авторизованной.
* Агенты роутеров подключаются исходящим соединением к домену и переподключаются
  сами; повторная привязка не нужна.
* Токены агентов хранятся в базе в виде хешей — они переезжают вместе с данными.
* HTTPS-сертификат должен быть доступен новому серверу (Caddy получит свой
  сертификат по тому же домену).

## Порядок переезда

1. Снизьте TTL DNS заранее (например, до 300 секунд).
2. Поднимите новый сервер и импортируйте данные.
3. Убедитесь, что новый сервер отвечает по IP, роутеры онлайн, задачи проходят.
4. Переключите DNS на новый сервер.
5. Старый сервер оставьте включённым на сутки как страховку, затем остановите.

## Ограничения

* Импорт заменяет **все** данные текущего экземпляра.
* Файл переноса нельзя восстановить без парольной фразы.
* Если файл создан более новой версией панели, импорт отклоняется: сначала
  обновите RoutX на новом сервере.
* Мастер-ключ хранится в томе `rc_data`. При пересоздании тома без импорта
  секреты станут нечитаемыми — держите экспорт и парольную фразу.

## HTTPS на OpenWrt

Готовая схема с Caddy на 443 и LuCI на 8443 лежит в `deploy/openwrt/`.
Сертификат выдаётся Let's Encrypt через TLS-ALPN, порт 80 не используется.
A-запись DuckDNS обновляет служба `routx-ddns` из `deploy/openwrt/ddns/`.
