# Сброс пароля и ссылки приглашений

## Ссылка приглашения

Ссылка создаётся в разделе **«Пользователи» → «Пригласить»**. Формат:

```text
https://routx.example/#/invite/<token>
```

Токен находится во фрагменте (`#`), поэтому не попадает в журналы reverse proxy.
Старые ссылки вида `/invite?token=…` тоже поддерживаются: фронтенд разбирает
путь и query, если хеша нет.

Если ссылку открыл уже вошедший пользователь, показывается предупреждение
«Вы уже вошли» с кнопкой выхода. Приглашение предназначено для новой учётной
записи.

Кнопка **«Скопировать ссылку»** использует Clipboard API на HTTPS/localhost и
резервный `document.execCommand('copy')` на HTTP. Если браузер запрещает
копирование, ссылку можно выделить прямо в модальном окне и скопировать
вручную.

## Самостоятельный сброс по коду 2FA

Если телефон с аутентификатором под рукой, пароль можно сбросить без почты:

1. На экране входа нажать **«Забыли пароль?»**.
2. Указать e-mail, 6-значный код из приложения и новый пароль.
3. После сброса все сессии завершаются. Вход — с новым паролем и кодом.

Ограничения:

* нужен уже включённый 2FA;
* 5 попыток за 15 минут с одного IP;
* код одноразовый: повторно тот же код не сработает;
* если телефона нет — остаются ссылка от администратора и CLI.

## Сброс пароля пользователю

Сброса по e-mail нет: SMTP не настроен, регистрация только по приглашению.
Если пользователь не может воспользоваться кодом 2FA, сброс выполняет
суперадминистратор:

1. **«Пользователи»** → у нужной учётной записи **«Восстановить доступ»**.
2. При необходимости включить **«Потерян телефон с 2FA»** — тогда вместе
   с паролем будет сброшен второй фактор.
3. Подтвердить создание ссылки.
4. Скопировать одноразовую ссылку и передать пользователю по защищённому каналу.

Ссылка:

```text
https://routx.example/#/reset-password/<token>
```

* действует 1 час;
* одноразовая;
* при создании новой ссылки предыдущие неиспользованные ссылки этого
  пользователя аннулируются;
* после смены пароля все активные сессии пользователя отзываются.

Пользователь открывает ссылку, задаёт новый пароль и входит. По умолчанию TOTP
сохраняется. Если был включён сброс 2FA, при входе потребуется заново
подключить приложение-аутентификатор — но только если этого требует политика
`all`/`admins`.

## Восстановление доступа: что именно сбрасывается

| Ситуация | Действие |
| --- | --- |
| Забыл пароль, телефон с 2FA есть | Самостоятельный сброс по коду 2FA |
| Забыл пароль, телефона нет | «Восстановить доступ» + галочка «Потерян телефон с 2FA» |
| Нет доступа к почте | E-mail используется только как логин; письма не отправляются, на вход это не влияет |
| Учётная запись заблокирована | Сброс пароля очищает `locked_until` и счётчик ошибок |
| Нужно выкинуть все сессии | «Отозвать сессии» в карточке пользователя |
| Пользователь в архиве | «Восстановить из архива» |

Почта при восстановлении не используется: SMTP в v1 не настроен, ссылку
передаёт администратор. Это сделано осознанно — не нужен внешний сервис,
а ссылка не уходит в спам.

Вход в систему содержит ссылку **«Забыли пароль?»**: там можно сбросить пароль
по коду 2FA, а если телефона нет — обратиться к суперадминистратору за ссылкой.

## Если суперадминистратор забыл пароль

Если в системе нет другого администратора, используется CLI на сервере:

```sh
npm run password-reset -w @routx/server -- admin@example.com
```

В production-контейнере:

```sh
docker compose exec app node server/dist/cli/password-reset.js admin@example.com
```

Если телефон с 2FA тоже потерян, добавьте `--reset-mfa`:

```sh
docker compose exec app node server/dist/cli/password-reset.js admin@example.com --reset-mfa
```

Команда печатает одноразовую ссылку сброса. Она использует `RC_PUBLIC_URL` и
пишет действие в аудит как `user.password_reset_cli`.
