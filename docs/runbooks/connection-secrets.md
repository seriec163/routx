# Компактные секреты подключения `rc1.…`

## Зачем

Обычная ссылка подписки или VLESS может быть длинной и содержать провайдерский
хвост. Компактный секрет хранит только то, что нужно для подключения:

* тип: подписка или VLESS;
* домен или IP;
* порт;
* учётные данные (токен подписки, UUID или пароль);
* при необходимости — путь, SNI, транспорт, security и flow.

Секрет можно заменить в подключении на странице роутера, не пересоздавая
подключение. RoutX расшифрует его, соберёт обычную ссылку и применит
на роутере через существующий безопасный сценарий: diff → подтверждение →
снимок → apply.

## Формат

```text
rc1.<base64url>
```

Внутри — AES-256-GCM:

* ключ выводится через HKDF-SHA256 из `RC_MASTER_KEY`;
* nonce 12 байт, тег 16 байт;
* AAD — `rc1`;
* открытый текст — компактная бинарная структура с длинами полей, без JSON.

Ориентировочная длина:

* VLESS с UUID, доменом и путём — около 120–170 символов;
* подписка с доменом, токеном и путём — около 120–180 символов.

Точная длина показывается в интерфейсе после генерации.

## API

`POST /api/v1/connection-secrets`

```json
{
  "kind": "vless",
  "host": "vpn.example.com",
  "port": 443,
  "credential": "uuid",
  "path": "/ws",
  "transport": "ws",
  "security": "tls"
}
```

Ответ:

```json
{
  "secret": "rc1....",
  "length": 143,
  "preview": {
    "kind": "vless",
    "host": "vpn.example.com",
    "port": 443,
    "credential_masked": "••••uuid"
  }
}
```

`POST /api/v1/connection-secrets/decode` — показать, что внутри секрета, без
сохранения. Учётные данные возвращаются только маской.

`POST /api/v1/routers/:id/connections` принимает либо `value` (обычная ссылка),
либо `secret` (`rc1.…`), либо `subscription_id`. Если `value` начинается с
`rc1.`, он обрабатывается как компактный секрет.

`PATCH /api/v1/routers/:id/connections/:connectionId` принимает `secret` или
`value` и заменяет секрет подключения. Это основной способ «поменять секрет».

`GET /api/v1/routers/:id/connections/:connectionId/secret` возвращает сохранённый
компактный секрет для копирования. Действие пишется в аудит как
`router.connection_secret_view`.

## Ограничения

* Секрет расшифровывается RoutX на сервере. Для офлайн-расшифровки
  непосредственно на роутере нужен отдельный ключ в агенте; текущая версия
  такого режима не включает.
* Поддерживаются типы `subscription` и `vless`, потому что только они есть в
  модели подключений RoutX.
* `security` поддерживает `tls` и `none`. Для Reality нужны дополнительные
  параметры (`pbk`, `sid`), которых пока нет в компактном формате.
* При смене `RC_MASTER_KEY` старые `rc1.…` перестанут расшифровываться. Их нужно
  пересоздать или перешифровать по процедуре ротации ключа.
