# Мониторинг и поэтапное обновление sing-box

## Мониторинг

Сервер раз в 60 секунд ставит задачу `monitor` для каждого роутера с включённым
мониторингом. Задача идёт через обычный канал агента, без входящих портов.

Агент (`jn_monitor.uc`) возвращает:

| Поле | Источник |
|---|---|
| `reachable` | агент выполнил команду — роутер доступен |
| `service_state` / `health` | `prokop get_health_status` + `get_status` |
| `proxy_health` | реальные задержки через Clash API |
| `latency_ms` | медиана задержек живых тегов |
| `failed_tags` / `total_tags` | сколько тегов группы не ответило |
| `detail` | например, `группа gga-out: 3/3 живых` |

Если служба запущена, но автозапуск выключен (`running but disabled`), это
считается деградацией: прокси может работать, но после перезагрузки роутер
поднимется без Prokop/Forkop. Вместе с продуктом не запустится и sing-box,
потому что Prokop/Forkop управляет им сам. Остановленная служба — `failed`.

Для sing-box отдельный автозапуск не требуется. Агент 1.1.4+ не считает
выключенный `/etc/rc.d/S99sing-box` деградацией, если Prokop/Forkop запущен и
включён: продукт поднимает sing-box самостоятельно.

Прокси-здоровье:

* `healthy` — в группе есть хотя бы одно живое соединение, задержка не выше 1500 мс;
* `degraded` — задержка выше 1500 мс;
* `dead` — ни один тег не ответил;
* `unknown` — Clash API недоступен или у секции нет группы прокси.

Если часть резервных соединений не отвечает, но группа переключается на живые,
она остаётся `healthy`: переключение на резервный сервер — не деградация.
Упавшие теги не теряются: агент передаёт их список, а панель показывает
«Нестабильные соединения» во вкладке «Метрики» — сколько раз каждое
соединение теряло связь за 24 часа и когда это было последний раз.

### Уведомления о деградации

Чтобы предупреждения не превращались в поток:

* сообщение отправляется после нескольких плохих проверок подряд
  (по умолчанию 3);
* одно сообщение на непрерывный эпизод деградации;
* между эпизодами действует пауза (по умолчанию 6 часов);
* «VPN снова работает» приходит один раз и только если до этого было
  отправлено предупреждение.

Настройки находятся в «Настройках сервера → Мониторинг»: «Проверок до
деградации», «Пауза уведомлений о деградации» и «Сообщать о восстановлении».

Активный замер группы (`clash_api get_group_latency`) выполняется не чаще раза
в 3 минуты на группу; между замерами используется история sing-box. Для групп
больше 30 тегов активный замер не запускается, чтобы не перегружать роутер.

Ручная проверка:

```http
POST /api/v1/routers/{id}/monitor
```

Кнопка «Проверить сейчас» на странице «Мониторинг» вызывает этот endpoint для
всех роутеров в сети.

Если в таблице `proxy_health = unknown`, проверьте на роутере:

```sh
prokop get_health_status
prokop clash_api get_proxies
prokop clash_api get_group_latency gga-out 3000
```

## Поэтапное обновление (staged rollout)

Это обновление sing-box сразу на нескольких роутерах волнами. Используется,
когда роутеров больше одного.

1. **Проверочный роутер** — обновляется один роутер.
2. **Первая волна** — примерно 25% оставшихся.
3. **Остальные** — все оставшиеся.

Между волнами кампания ждёт подтверждения администратора. Ошибка на волне
останавливает кампанию; уже обновлённые роутеры не откатываются автоматически.

Создание кампании:

* выбрать вариант: Tiny / Extended / Extended compressed / Stable;
* для Extended можно выбрать конкретную версию из каталога, для остальных
  ставится последняя версия пакетного репозитория;
* выбрать роутеры (или оставить пустым — тогда все подходящие);
* посмотреть, как распределятся волны.

Управление:

| Кнопка | Что делает |
|---|---|
| Запустить проверочный этап | переводит черновик в работу и обновляет 1 роутер |
| Следующая волна | доступна, когда текущая волна завершилась без ошибок |
| Приостановить | запрещает запуск новых волн; текущие установки не останавливает |
| Продолжить | снимает паузу |
| Отменить | отменяет ожидающие задачи; установленные версии остаются |

API:

```http
POST /api/v1/rollouts
POST /api/v1/rollouts/{id}/start
POST /api/v1/rollouts/{id}/advance
POST /api/v1/rollouts/{id}/pause
POST /api/v1/rollouts/{id}/resume
POST /api/v1/rollouts/{id}/cancel
```

Если роутер один, поэтапность не нужна: обновите sing-box во вкладке
«sing-box» на странице роутера.
