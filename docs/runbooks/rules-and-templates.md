# Правила, подключения и шаблоны

Начиная с версии 1.1.9 панель работает не с «шаблонами секций», а с
**правилами**. Правило — это одна секция Prokop/Forkop/Podkop на роутере.

## Что видно на странице роутера

Вкладка **«Правила и подключения»**:

1. Читает текущие секции прямо с роутера: действие, включено/выключено,
   ресурсы (`community_lists`), свои домены, IP, подписки и VLESS-ссылки.
2. Если правил нет — показывает пустое состояние и кнопку **«Добавить
   правило»**.
3. Позволяет менять правило без шаблона: действие, ресурсы, домены,
   подключения, включение/выключение.
4. Позволяет добавить новое правило и сразу вставить URL подписки или
   VLESS-ссылки.

Пример «только YouTube через VPN»:

1. **Добавить правило**.
2. Название: `YouTube`.
3. Действие: **Через VPN-подключение**.
4. Ресурсы: **YouTube** (при необходимости — свои домены).
5. Вставить URL подписки или VLESS-ссылки.
6. Нажать **«Показать изменения»** и подтвердить.

## Шаблон

Шаблон — это **пресет**, а не привязка к имени секции:

* действие (через VPN, в обход, блок, только DNS);
* список ресурсов (сервисы, свои домены, IP, URL-списки);
* глобальные настройки (DNS, логи, QUIC и т. п.).

В шаблоне **нет имени секции**. На роутере вы открываете нужное правило и
выбираете шаблон в поле **«Заполнить из шаблона»** — форма заполняется его
значениями. Дальше сохраняете правило обычным способом.

Подписки и VLESS-ссылки в шаблон не входят и шаблоном не перезаписываются.

## Развёртывание шаблона на несколько роутеров

В шаблоне есть кнопка **«Развернуть»**:

1. отметьте роутеры — свои и, для администратора, роутеры пользователей
   своей ветки;
2. нажмите **«Подготовить diff»** — панель запросит изменения на каждом
   роутере, ничего не записывая;
3. проверьте diff и нажмите **«Развернуть»** на нужном роутере или
   **«Развернуть все»**;
4. панель создаст снимок, применит шаблон, проверит результат и при ошибке
   откатится.

Прогресс и ошибки видны в разделе **«Применения»**. Суперадминистратор
может разворачивать шаблон на любые роутеры, администратор — на свои и на
роутеры своей ветки, пользователь — только на свои.

## Podkop

Для Podkop правило — это секция с типом `proxy`, `vpn`, `block` или
`exclusion`. В форме правила доступны:

* **Community Lists** — те же сервисы из каталога, что у Prokop/Forkop;
  списки, которые Podkop не поддерживает (`github`, `supercell`),
  отфильтровываются автоматически;
* **User Domain List Type**:
  * `dynamic` — список UCI `user_domains`, по одному домену на строку;
  * `text` — текстовый список `user_domains_text` (домены через запятую или
    по одному на строку);
  * `disabled` — не использовать;
* **User Subnet List Type** — так же: `user_subnets`, `user_subnets_text`
  или `disabled`;
* подключения `url`, `selector`, `urltest`;
* готовый `outbound_json` — RoutX сохраняет его и не перезаписывает
  ссылками; в режиме `outbound` можно вставить новый JSON целиком
  (текущее значение скрыто). Замена проверяется через `sing-box check`,
  при ошибке конфиг откатывается;
* низкоуровневые параметры: UDP over TCP, mixed proxy, domain resolver,
  resolve real IP, интервал/допуск/URL urltest, порт mixed proxy;
* импорт подписки: RoutX скачивает URL, разбирает `vless/ss/trojan/
  hysteria2/socks`-ссылки и добавляет их как отдельные подключения
  Podkop. Сама подписка на роутер не передаётся;
* при добавлении подписки к роутеру с Podkop разбор происходит
  автоматически: в список попадают отдельные подключения, а не подписка;
* у каждого подключения показывается активность, задержка и доступность
  из Clash API (`get_proxies`, история sing-box). Отдельный тест не
  запускается;
* активное подключение можно переключить кнопкой «Выбрать»
  (`set_group_proxy` через Clash API).

После сохранения RoutX делает снимок `/etc/config/podkop`, записывает
изменения, выполняет `podkop reload`, проверяет `sing-box check` и запуск
службы. При ошибке конфиг автоматически откатывается.

Шаблон может содержать блок **Podkop** (`connection_type`,
`proxy_config_type`, `user_domain_list_type`, `user_domains_text`,
`user_subnet_list_type`, `user_subnets_text`). При применении к Podkop
используется этот блок, а `action` маппится в тип секции:
`connection → proxy`, `bypass → exclusion`, `block → block`. Для
Prokop/Forkop блок Podkop игнорируется.

## Общий доступ к шаблонам

По умолчанию шаблон виден только владельцу. В списке **«Шаблоны»** у
своего шаблона есть кнопка **«Сделать общим»**:

* шаблон появляется у всех пользователей панели с бейджем **«Общий»**;
* другие пользователи видят его и могут применять к своим роутерам;
* редактировать, архивировать и удалять шаблон может только владелец
  (и superadmin);
* кнопка **«Сделать личным»** снова скрывает шаблон от остальных;
* уже применённые к роутерам правила не меняются при скрытии доступа.

## Безопасность изменений

* Перед записью показывается diff: какие параметры добавятся, изменятся или
  удалятся.
* Перед применением создаётся снимок конфигурации.
* После записи выполняется reload и проверка состояния.
* При ошибке RoutX восстанавливает снимок.
* Выключение правила не удаляет его подключения и списки.
* Prokop требует хотя бы одно включённое правило. Панель не даёт выключить
  последнее включённое правило и удалить последний источник подключения у
  него — иначе Prokop пишет `no enabled sections` и не собирает конфигурацию.

## Совместимость

Старые шаблоны с именами секций читаются: если в шаблоне одна секция, её
действие и ресурсы показываются как пресет. При сохранении шаблон
переводится в новый формат без имени секции. Старые назначения шаблонов на
роутеры продолжают работать по прежней ревизии, но в интерфейсе роутера
больше не показываются.
