# Подбор DNS для Prokop/Forkop

Реализация написана самостоятельно. Tachyon (GPL-2.0) использован только как
исследование: его алгоритм не копировался, а спорные места (`curl -k`, два
домена на весь тест, автоматическое применение) заменены.

## Требования

Нужен агент RoutX **1.1.0+**. Обновление на роутере:

OpenWrt 24.10 / opkg:

```sh
wget -qO /tmp/routx-agent.ipk https://routx.example/agent/routx-agent.ipk
opkg install --force-reinstall /tmp/routx-agent.ipk
/etc/init.d/routx-agent restart
```

OpenWrt 25+ / apk:

```sh
wget -qO /tmp/routx-agent.apk https://routx.example/agent/routx-agent.apk
apk add --upgrade --allow-untrusted --force-overwrite /tmp/routx-agent.apk
/etc/init.d/routx-agent restart
```

`/etc/config/routx` при обновлении сохраняется.

## Что меняется

Панель управляет только глобальными DNS-настройками Prokop/Forkop:

```text
prokop.settings.dns_type
prokop.settings.dns_server
prokop.settings.bootstrap_dns_server
```

Системный dnsmasq, DHCP и секционные DNS-правила не изменяются.

Поддерживаются только:

- `dns_type=udp` с IP-адресами серверов;
- `dns_type=doh` с `https://…` URL.

Prokop допускает `dot` и `doq`, но первая версия подбора их не тестирует.

## Как работает замер

Кнопка **«Проверить DNS»** на вкладке **DNS** запускает фоновый worker
`jn_dns_benchmark.uc` на роутере через агент 1.1.0+.

Worker:

- проверяет 13 UDP и 17 DoH резолверов;
- использует 10 стандартных доменов;
- делает по 5 замеров на пару «сервер × домен»;
- DoH-кандидаты Google, Cloudflare, Quad9 и Yandex проверяются по IP-адресу
  в URL (`https://8.8.8.8/dns-query`, `https://1.1.1.1/dns-query` и т.п.),
  без резолва hostname;
- для DoH проверяет TLS-сертификат (без `curl -k`), HTTP-статус, формат
  DNS-ответа и совпадение вопроса;
- для UDP использует `dig`, при его отсутствии — `nslookup`;
- считает медиану, p95, потери и score;
- отдельно помечает фильтрующие DNS;
- отдельно помечает подозрительно быстрые UDP-ответы (< 5 мс): это может быть
  локальный кэш или перехват DNS провайдером. Такие серверы не попадают в
  рекомендацию по умолчанию.

Bootstrap для DoH — фиксированный список IP-адресов:

```text
77.88.8.8, 8.8.4.4, 1.1.1.1, 9.9.9.9
```

В рекомендацию DoH попадает до трёх провайдеров. Применение принимает до
четырёх основных DNS и до четырёх bootstrap-серверов.

Прогресс и отмена выполняются через обычную очередь задач. Один тест на роутер
одновременно.

## Как применяется

1. Пользователь выбирает лучший UDP или лучший DoH набор.
2. Панель формирует diff только по трём DNS-настройкам.
3. Сервер создаёт `apply_run` и показывает diff.
4. После подтверждения создаётся снимок.
5. Агент применяет UCI, перезагружает Prokop/Forkop.
6. Сервер читает состояние и проверяет, что значения записались.
7. При ошибке выполняется откат снимка.

Секции с собственным `dns_type`/`dns_server` не меняются; панель показывает
предупреждение.

## Detour

Если включён `settings.dns_detour_enabled`, DNS идёт через выбранную секцию.
Прямой замер с роутера не отражает этот путь, поэтому применение DNS-кандидатов
**блокируется**. Нужно:

1. выключить detour в Prokop/Forkop;
2. подобрать DNS;
3. применить;
4. включить detour обратно.

После включения detour скорость может измениться — это ожидаемо.

## Ограничения

- Замер идёт с самого роутера, а не с клиентских устройств.
- CDN и геолокация зависят от резолвера: быстрый DoH может вернуть дальний
  CDN-адрес.
- UDP может перехватываться провайдером; такие ответы помечаются.
- IPv6, DoT и DoQ в первой версии не тестируются.
- Результаты зависят от времени суток и текущей загрузки канала.
- Шаблон может управлять DNS; в этом случае ручное применение блокируется.
